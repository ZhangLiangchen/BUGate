# BUGate v0.4.4

[English](v0.4.4.md) | [简体中文](v0.4.4.zh-CN.md)

Status: source release notes for the v0.4.4 patch. This file does not by
itself prove tag creation, CI completion, asset publication, or public-download
reacceptance; those remain release-operation gates.

BUGate v0.4.4 makes an existing imported installation upgradeable through the
same agentic interface used for the rest of BUGate. It adds a dedicated
`bugate-update` skill, a portable bilingual update prompt, and executable
contracts that bind natural-language discovery, authorization boundaries, and
the installed projection.

## Dedicated agent update entry

The release adds:

- `.shared/skills/bugate-update/SKILL.md`, whose frontmatter explicitly covers
  requests such as “update BUGate,” “upgrade BUGate,” “change the BUGate
  version,” “升级 BUGate 版本,” and “升级BUGate版本”;
- `.shared/skills/bugate-update/agents/openai.yaml`, with
  `allow_implicit_invocation: true` and a `$bugate-update` default prompt;
- top-level [`UPDATE_PROMPT.md`](../../UPDATE_PROMPT.md) and
  [`UPDATE_PROMPT.zh-CN.md`](../../UPDATE_PROMPT.zh-CN.md), which can be pasted
  into Codex or Claude Code; and
- discovery links for Claude, official Codex `.agents/skills`, and the legacy
  `.codex/skills` bridge.

The installer and updater now project the skill, both prompts, and all three
runtime links into every compatible imported installation. The Codex plugin
default prompt also routes natural-language version-upgrade requests to the
dedicated skill.

## Authority and workflow contract

The update skill defaults to `PLAN_ONLY`. That authority permits read-only
workspace discovery plus updater `status` and `plan`; it does not permit
`apply`, rollback, profile migration, lineage operations, commit, push, tag, or
Release publication.

An existing installation is classified by physical evidence:

```sh
if test -f "$BUGATE_VENDOR_DIR/bugate.lock.json" \
  && test -x "$BUGATE_VENDOR_DIR/bin/bugate-update"; then
  BUGATE_ROUTE=locked-in-repo-update
else
  BUGATE_ROUTE=external-bootstrap-candidate
fi
```

A locked installation uses the vendored launcher. An exact supported v0.3.x or
pre-lock v0.4.0/v0.4.1 installation uses a checksum-verified, unpacked
v0.4.2-or-later external updater. Unknown, mixed, partial, or locally modified
managed state remains `NO-GO`. There is no implicit `latest`, no broad
`--force`, and no fallback to the fresh-install-only `bugate_init.py`.

Only explicit authority for the exact target/source and reviewed
`Decision: GO` plan enters `APPLY_APPROVED`. The agent then repeats the same
source inputs through `apply`, requires `verify` and imported smoke to pass,
and reports the exact managed diff, transaction ID, hook/session actions, and
rollback route.

## Ownership remains unchanged

The new agent surface orchestrates the existing transactional updater; it does
not expand updater ownership. Engine update still excludes:

- `bugate.config.yaml`, `bugate.profile.yaml`, and other SUT-owned profile
  decisions;
- SUT tests, fixtures, use-case artifacts, and unrelated dirty files;
- `00_role_evidence/**`, Memory namespace/data, and the machine lineage
  registry; and
- SUT-owned hooks, skills, credentials, and product facts.

Profile migration and per-UC `lineage-init`, `lineage-adopt`, or `recover`
remain separately reviewed actions. Updater installation success is not
lineage-migration acceptance. Commit and push also remain separate authorities
unless the operator explicitly grants them.

## Compatibility

`bugate_init.py` remains fresh-install-only. The updater protocol floor remains
v0.4.2, so exact supported legacy/pre-lock installations continue to bootstrap
from a verified unpacked v0.4.2-or-later release without rewriting old
receipts. v0.4.3 role-lineage semantics and the `evidence_recovery` event are
unchanged.

## Contract and publication gates

New SUT-neutral contract tests pin:

- exact skill metadata and English/Chinese natural-language trigger phrases;
- implicit invocation metadata and the explicit `$bugate-update` route;
- bilingual prompt links, plan-only defaults, and apply/profile/lineage/git
  authority separation;
- the lock-plus-launcher classifier and the absence of `latest`/`--force`
  shortcuts;
- inclusion of the new artifacts in the installer/updater manifest; and
- Codex plugin routing for version-upgrade requests.

The normal compile, discovery, direct-file, de-SUT, pre-code semantic, and
imported updater regression suites remain mandatory. Formal archive acceptance
must use the exact flags
`--full-check-mode smoke --full-check-archive both` against independently
unpacked tar and zip artifacts.

That smoke workflow retains the v0.4.3 lineage oracle: six lifecycle events
plus one state-preserving `evidence_recovery` receipt, for seven exact anchors.
Semantic release review remains provider-neutral. Cross-provider review is
preferred; if a provider is unavailable, only a newly spawned same-provider
session with an independent prompt and no access to the first conclusion before
synthesis is an acceptable fallback. Placeholder output, a continued session,
self-review, or an outage relabeled as success does not satisfy that gate.

The release distribution must contain exactly:

```text
bugate-0.4.4.tar.gz
bugate-0.4.4.zip
bugate-0.4.4.SHA256SUMS
```

Final SHA-256 values are generated only from the clean merged commit. The
acceptance JSON is evidence, not a public release asset.
