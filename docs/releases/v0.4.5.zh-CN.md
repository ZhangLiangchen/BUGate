# BUGate v0.4.5

[English](v0.4.5.md) | [简体中文](v0.4.5.zh-CN.md)

状态：v0.4.5 minor release 的源码 release notes。本文自身不证明 tag 已创建、
CI 已完成、assets 已发布或 public-download reacceptance 已通过；这些仍是 release
operation gate。

BUGate v0.4.5 新增受治理的测试资产自愈：为「这次失败是测试资产坏了」提供一条通往
已评审、绑定证据的修复的路径，并把它锚在 sidecar 上而不是冻结的 role-evidence 链
上。该能力**默认关闭**，其授权边界刻意很窄。

## 失败归因与自愈 sidecar

post-run 层此前只能分类失败，不能归因。`PATTERNS` 按裸子串匹配且无词边界，于是一行
关于 pooled connection 的 debug 日志就足以把 `sut_defect_admissible` 结构性钉死为
`False`。本版本新增带锚点与反例的归因（`failure_owner`、`failure_subtype`）；证据不
充分时返回 `insufficient_evidence` 且 `healing_eligible: false`，绝不猜测 owner。

修复通过 `<artifact_dir>/00_self_healing/` 下的六事件 sidecar 受治理：triage、
handoff、accept、propose、绑定的独立评审、close。之所以用 sidecar，是因为主
role-evidence 链是冻结的——post-run 阶段以 implementer 身份行动的 healer 永远不可能
是合法的主链 actor，而向某个 UC 主链写入一个未知事件会让 v0.4.0–v0.4.4 的任何引擎
读该链时整体失败。设计记录见
[`BUGATE_SELF_HEALING_SIDECAR_ADR.md`](../qa-methodology/BUGATE_SELF_HEALING_SIDECAR_ADR.md)
（ADR-BUGATE-005）。

## 默认关闭，且关闭时逐字节一致

`self_healing.mode` 默认 `off`。从未设置 `self_healing` 的仓库行为与 v0.4.4 完全
一致：`--scope self-heal` 返回 `disabled`、退出码 0 且零创建；`--scope post-run`
产物与 v0.4.4 逐字节相同——由 v0.4.4 引擎实测生成的 golden fixture 钉死。`verify`
模式在 workspace 副本中证明修复，绝不写真实目录树；只有 `apply_with_approval` 才写
回，且必须先完成完整评审流程与人工批准记录，只写 profile `allowed_write_regex` 指定
的路径，并且只通过在首次写入前记录每个目标确切原字节的 journal 写入。

## 授权边界很窄，并且写明

动态反例只是一次证伪观测。任意 Python 都能识别任何有限的、候选可见的 mutant，因此
一次干净的动态击杀本身不构成诚实性证明。自动授权因此被限制在两条闭合、可判定的候选
语言内：engine 自导的 NameError/literal 修复，以及 canonical 外部 JSON 证据断言。
其余任何候选形态一律停在 exit 2——blocked，且不向 workspace 或 sidecar 写入任何字节。

exit 3（「修好的测试在声明的 oracle 违例下仍然通过」）只在断言绑定由上述闭合语言内的
**静态**证明承载时才会给出，绝不由被测候选自己产出的证据推导：引擎与候选运行在同一
解释器里，候选可以先从自己的源码中读出被注入的探针再决定输出什么，因此任何带内执行
见证都无法确立该绑定。代价被写明而不是隐藏——确实存在真的假绿候选只被拦下而不被指名。
完整边界与实测授权率见 [`CAPABILITIES.md`](../../CAPABILITIES.md)。

## 验证随仓库一起执行

本版本同时纳入评审该能力时发现的两个缺陷的回归底线，以及一个 exact-one-anchor 引擎
变异 harness（`tests/test_engine_mutation_guards.py`）：它向引擎副本注入**恰好一处**
带锚点的改动，并要求唯一被指名的守卫失败。九个 mutant 覆盖结构 finding 码、
review-manifest 绑定、apply 分支、sidecar 状态迁移守卫、sidecar 完整性 reason、
两类附带写入泄漏，以及两个断言绑定修复。anchor 不存在或不唯一时 harness 拒绝注入，
因此一次「什么都没改」的注入不可能被记为守卫通过。

## 兼容性

`bugate_init.py` 继续只负责 fresh install。Updater protocol floor 仍为 v0.4.2。
v0.4.3 role-lineage 语义、`evidence_recovery` event，以及 v0.4.4 的 `bugate-update`
skill 与双语升级 Prompt 均不变。未向冻结的 governed evidence layout 新增任何叶子；
自愈证据落在 `00_self_healing/`，绝不进入 `00_role_evidence/`。

## Contract 与发布门

常规 compile、discovery、逐文件、de-SUT、pre-code semantic 与 imported updater
regression suite 均为必跑项。正式 archive acceptance 必须对独立解包的 tar 与 zip
使用精确参数 `--full-check-mode smoke --full-check-archive both`。

该 smoke workflow 保留 v0.4.3 lineage oracle：六个 lifecycle event 加一条保持状态的
`evidence_recovery` receipt，共七个 exact anchor。Semantic release review
保持 provider-neutral。优先跨 provider；若某 provider 不可用，只接受使用独立
prompt 且在 synthesis 前看不到首个结论的**新建同源** session 作为 fallback。
Placeholder output、延续旧 session、self-review 或把 outage 改写为成功都不满足门禁。

Release distribution 必须且只能包含：

```text
bugate-0.4.5.tar.gz
bugate-0.4.5.zip
bugate-0.4.5.SHA256SUMS
```

最终 SHA-256 只从干净的 merged commit 生成。Acceptance JSON 是证据，不是公开
release asset。
