# BUGate v0.4.4

[English](v0.4.4.md) | [简体中文](v0.4.4.zh-CN.md)

状态：v0.4.4 patch 的源码 release notes。本文自身不证明 tag 已创建、CI 已完成、
assets 已发布或 public-download reacceptance 已通过；这些仍是 release operation
gate。

BUGate v0.4.4 让已有 imported installation 可以通过与 BUGate 其他能力一致的
agentic 入口完成升级。它新增专用 `bugate-update` skill、可复制的双语升级 Prompt，
并以 executable contract 固定自然语言发现、授权边界和 installed projection。

## 专用 agent 升级入口

本版本新增：

- `.shared/skills/bugate-update/SKILL.md`，其 frontmatter 显式覆盖
  “update BUGate”“upgrade BUGate”“change the BUGate version”与“升级 BUGate
  版本”“升级BUGate版本”等请求；
- `.shared/skills/bugate-update/agents/openai.yaml`，包含
  `allow_implicit_invocation: true` 和 `$bugate-update` default prompt；
- 顶层 [`UPDATE_PROMPT.md`](../../UPDATE_PROMPT.md) 与
  [`UPDATE_PROMPT.zh-CN.md`](../../UPDATE_PROMPT.zh-CN.md)，可直接粘贴给 Codex
  或 Claude Code；
- Claude、官方 Codex `.agents/skills` 与 legacy `.codex/skills` bridge 的
  discovery links。

Installer 与 updater 现在会把该 skill、两份 Prompt 和三套 runtime link 一起投影到
所有兼容 imported installation。Codex plugin default prompt 也会把自然语言版本升级
请求路由到专用 skill。

## 授权与工作流契约

Update skill 默认处于 `PLAN_ONLY`。该权限只允许只读 workspace discovery、updater
`status` 与 `plan`；不允许 `apply`、rollback、profile migration、lineage
operation、commit、push、tag 或 Release 发布。

已有安装按物理证据分类：

```sh
if test -f "$BUGATE_VENDOR_DIR/bugate.lock.json" \
  && test -x "$BUGATE_VENDOR_DIR/bin/bugate-update"; then
  BUGATE_ROUTE=locked-in-repo-update
else
  BUGATE_ROUTE=external-bootstrap-candidate
fi
```

Locked installation 使用 vendored launcher。精确匹配受支持 v0.3.x 或 pre-lock
v0.4.0/v0.4.1 的安装，使用位于仓外、已校验 checksum 并解包的 v0.4.2 或更高
updater。未知、混合、残缺或 managed path 已本地修改的状态保持 `NO-GO`。不存在
隐式 `latest`、宽泛 `--force`，也不能退回 fresh-install-only
`bugate_init.py`。

只有对 exact target/source 和已复核 `Decision: GO` plan 的明确授权才进入
`APPLY_APPROVED`。随后 agent 使用相同 source input 执行 `apply`，要求 `verify`
与 imported smoke 通过，并报告 exact managed diff、transaction ID、
hook/session action 与 rollback route。

## Ownership 保持不变

新的 agent surface 只是编排既有 transactional updater，不扩大 updater ownership。
Engine update 仍不触碰：

- `bugate.config.yaml`、`bugate.profile.yaml` 与其他 SUT-owned profile decision；
- SUT tests、fixtures、use-case artifacts 与无关 dirty files；
- `00_role_evidence/**`、Memory namespace/data 与 machine lineage registry；
- SUT-owned hooks/skills、credential 与产品事实。

Profile migration 以及 per-UC `lineage-init`、`lineage-adopt`、`recover` 仍是独立
评审动作。Updater 安装成功不等于 lineage migration 已验收。Commit 与 push 也保持
独立授权，除非 operator 明确批准。

## 兼容性

`bugate_init.py` 继续只负责 fresh install。Updater protocol floor 仍为 v0.4.2，
因此精确支持的 legacy/pre-lock 安装可以继续从已验证并解包的 v0.4.2 或更高 release
bootstrap，且不重写旧 receipts。v0.4.3 role-lineage 语义与
`evidence_recovery` event 保持不变。

## Contract 与发布门

新增 SUT-neutral contract tests 固定：

- exact skill metadata 与中英文自然语言触发短语；
- implicit invocation metadata 与显式 `$bugate-update` 路径；
- 双语 Prompt 链接、plan-only 默认值，以及 apply/profile/lineage/git 授权分离；
- lock-plus-launcher classifier 和不存在 `latest`/`--force` shortcut；
- 新 artifacts 已进入 installer/updater manifest；
- Codex plugin 对版本升级请求的路由。

常规 compile、discovery、逐文件、de-SUT、pre-code semantic 与 imported updater
regression suite 均为必跑项。正式 archive acceptance 必须对独立解包的 tar 与 zip
使用精确参数 `--full-check-mode smoke --full-check-archive both`。

该 smoke workflow 保留 v0.4.3 lineage oracle：六个 lifecycle event 加一条保持状态的
`evidence_recovery` receipt，共七个 exact anchor。Semantic release review
保持 provider-neutral。优先跨 provider；若某 provider 不可用，只接受使用独立
prompt 且在 synthesis 前看不到首个结论的**新建同源** session 作为 fallback。
Placeholder output、延续旧 session、self-review 或把 outage 改写为成功都不满足门禁。

Release distribution 必须且只能包含：

```text
bugate-0.4.4.tar.gz
bugate-0.4.4.zip
bugate-0.4.4.SHA256SUMS
```

最终 SHA-256 只从干净的 merged commit 生成。Acceptance JSON 是证据，不是公开
release asset。
