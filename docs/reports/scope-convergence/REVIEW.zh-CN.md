# 集成与独立评审

简体中文 | [English](REVIEW.md)

评审范围是正式F-01～F-08，不是强制SC清单。主控核对来源、协议变更、CLI/core/adapter边界、
报告一致性及产物证据；独立审查者按改造前行为复现了具名声明回归；核心实现者交叉核验实际DSH类型和参数转发；
打包审查检查了建议草稿是否影响快照。

已解决、直接影响真实目标的问题：

- **Profile权威**：早期草稿允许scope覆盖Profile分母。基线复核和用户纠正后恢复锁定分母；
  改变分母必须显式新Profile/task，原任务及失败保留。
- **用户来源**：真实DSH把模型创建的child prompt标为user-source，仅看角色会伪造同意。
  适配器同时检查session origin，排除fork继承消息，内部返工使用独立来源，真实子Agent回归验证该边界。
- **辅助与诊断准入**：补证操作不应先要求证据齐备。辅助按声明策略准入；诊断需当前有效受管失败并消耗持久化有限预算。
  辅助观察不冒充验收用例。
- **结果真实性**：遗漏有效失败不能让功能汇总通过；进程非零但没有失败业务Oracle保持执行问题。
  报告和结构化结果依据受管观测而非模型标签。
- **建议持久化**：真实DSH发现新增建议后重评同一声明会冲突。现将建议视图单独绑定到评估请求身份，
  声明、执行输入及授权快照保持不变。保留原失败和真实链路复验，见[运行发现](dsh/RUNTIME_FINDINGS.zh-CN.md)。
- **具名需求与整体闭环**：独立审查复现R1验证被未观察R2错误阻塞。修复后具名声明可通过，整体执行仍不完整，
  声明实际范围独立表达。针对性测试修前FAIL、修后PASS，最终完整core123项通过，
  见[独立证据](evidence/independent-review.json)。

当前无未解决评审项。本评审不证明任意业务语义正确，也不承诺抵抗同权限文件所有者恶意篡改。
来源语义判断、确定性引用检查与受管执行观察仍分开。适配器约束实际可观察的受管工具，
不宣称识别任意shell业务语义或覆盖所有native文件写入。
注册写入使用原子/CAS历史，独立修改事实会使评估失效。最终runtime/安装包证明见交付报告，不能仅从代码评审推断。
