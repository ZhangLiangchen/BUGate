# 冻结验收矩阵

简体中文 | [English](ACCEPTANCE_MATRIX.md)

来源：2026-10-29 用户请求 SC-01～SC-18。本矩阵用于开发验收，实际测试名和结果在执行后另行登记，
这里不预先标记通过。R 编号见[实施合同](CONTRACT.zh-CN.md)。

| 用例 | 需求 | 必须观察到的结果 | 层级 |
|---|---|---|---|
| SC-01 | R1/R3 | 普通用户下单仅生成必要流程，验证真实业务结果，不自动加入安全/模糊/并发/性能矩阵。 | core + fixture |
| SC-02 | R2 | 用户指定跨租户拒绝成为必测，并以预期拒绝为 Oracle。 | core + fixture |
| SC-03 | R2 | 指定正常、边界、失败三类全部保留。 | core |
| SC-04 | R5/R10 | 登录、准备、读证据、清理作为合法辅助活动放行，不变成目标。 | core + DSH |
| SC-05 | R3/R4 | 无必要关联的提议只作建议，未经变更不能升级必测或执行。 | core + DSH |
| SC-06 | R4 | 主流程证据齐备且通过，有多条建议仍可完成且不返工。 | core + DSH |
| SC-07 | R8/R11 | 真实失败证据齐备可完成执行，功能结论失败，保留断言和失败。 | core + DSH |
| SC-08 | R1/R11 | 缺关键业务证据时结构/model pass 不能授权闭环。 | core + DSH |
| SC-09 | R5 | 诊断关联当前失败并在边界停止，保存结果或阻塞。 | core + DSH |
| SC-10 | R6/R7 | 用户扩展产生新版本/历史，旧计划失效，新增场景进入必测。 | core + DSH |
| SC-11 | R6/R8 | 因失败缩减范围或伪造授权不能获得完成许可。 | core + DSH |
| SC-12 | R9 | 重启、冷恢复、压缩、child、preset 恢复同一有效契约。 | 真实 DSH |
| SC-13 | R7 | 旧范围/计划/快照评估不能授权新声明或执行。 | core + DSH |
| SC-14 | R9 | 并行任务计划、建议、证据、评估隔离。 | core + DSH |
| SC-15 | R1/R3/R6 | 排除冲突和必要性无来源产生明确缺口，不静默猜测。 | core |
| SC-16 | R4/R7/R12 | 已安装包在真实 DSH 确定性模型主动扩展时拒绝，持久化建议和证据并收敛完成。 | 已安装真实 DSH |
| SC-17 | R12 | 禁止访问源仓库的干净安装运行核心范围流程；重复安装/doctor/升级/回滚/卸载通过。 | package + OS 边界 |
| SC-18 | R4/R8/R11 | 报告分开实际范围、执行完整、功能结果、阻塞、建议和有限结论。 | core + report |

适用回归包括：真实执行来源、无执行/model pass/hash 反例、快照和声明摘要、持久化屏障、
取消与超时、路径/符号链接、并发冲突、执行环境映射、安装所有权与生命周期、恢复和子 Agent 隔离。
既有 core/runtime 套件继续作为验收输入。
替换无条件负向矩阵规则时必须保留 SC-02/03 对明确指定负向、权限、边界的验证。
