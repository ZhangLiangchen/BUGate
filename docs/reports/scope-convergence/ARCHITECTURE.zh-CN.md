# 验收范围架构决策

[English](ARCHITECTURE.md) | 简体中文

本次变更依据是用户产品请求和业务不变量，以及随后明确“SC-01～SC-18 是候选例子，不是强制清单或固定完成门槛”的纠正。[实现合同](CONTRACT.zh-CN.md)与[采纳验证映射](ACCEPTANCE_MATRIX.zh-CN.md)记录推导过程，不能反过来作为自身规则的独立授权。

已重新读取不可变基线 `fe3e29b82059504cd47893b72005051489c0810f` 的 AGENTS、METHOD、SOP、协议指南、`protocol/v2/rules/quality.json`、test-design MethodSpec 及评估器。基线要求 Profile 固定分母、有来源 Oracle、精确快照、真实执行证据并保留产品失败；无条件负例规则明确存在于 `quality.json.negative_coverage` 和 `assessment.py` 的 `NEGATIVE_COVERAGE_MISSING`。不得引用刚改的新文件反向证明修改基线规则已经获得授权，见[基线复核记录](packaging/basis-review.json)。

1. **第一等范围实体，复用现有计划。** 契约版本不可变并带内容摘要；现有 inventory 表达可执行必需用例，要求/Oracle 保留原事实来源。建议单独存储，不进入验收分母；每个版本均保持锁定 Profile 分母，契约不能静默覆盖它，避免第二套计划或状态机权威。建议内容具有独立的评估请求摘要，建议列表变化可生成一致的不可变结果，而不改变受管输入快照或增加执行义务。
2. **广度有限，深度充分。** 必需用例需要目标关联和业务证据，不再无条件套用正常/异常/边界矩阵。明确要求的拒绝、边界、权限及多目标必须保留。由用户的广度/深度决策授权替换旧的无条件负例扩张，不以候选用例编号作授权。已采纳测试证明该行为并保留明确要求的负例断言；候选编号仅用于历史追踪。
3. **用户意图来源属于宿主边界。** 契约文字不能认证自身授权。DSH 输入接缝必须区分真人直接消息、委派提示、fork 继承消息和内部返工。目标宿主 `dsh-subagent/lib/types/manager.js` 会把委派提示标记为 user，因此只检查 role/source 不足。适配器另查会话 origin，仅登记允许的用户原始输入；子 Agent 恢复同一契约但不创造新用户授权。
4. **执行前评估。** Python 核心基于有效范围、inventory 和当前快照，为声明的用例和有界辅助活动生成评估结果。DSH 在可等待准备/工具接缝消费；同步 context/guard 只读完成后的准备状态。不推断任意 shell 命令的全部业务语义，宿主权限和 execution provider 仍具有权威。
5. **执行完成可以包含功能失败。** 交付闭环需要约定观测和一致报告，需求验证要求实际 Oracle 成立。建议不触发返工，范围内缺失/无效证据才触发。产品真实失败必须保留。
6. **变更使旧授权失效。** 锁定 Profile 同分母内，用户授权的分支/Oracle 变更新建范围版本并记录影响、保留历史。分母变化由 `SCOPE_PROFILE_CHANGE_REQUIRED` 拒绝并引导显式新 Profile 版本和 `init` 新任务；不实现同任务 Profile rebind 或迁移引擎。可在新 Profile source 引用旧契约快照保留跨任务追溯，原任务和失败始终保留。ScopeRequest 证明用户选择，不替代 Profile 声明的领域证据。计划和声明评估必须匹配精确摘要/版本。本版本保守地将旧范围证据全部判为不适用并要求重新运行，保留历史，不提供选择性复用。Agent 自填批准或因失败缩减范围不能授权新完成声明。
7. **有限分发，可独立验证。** 新增三份范围 Schema 与 acceptance MethodSpec 从同一显式清单进入 Python wheel 和原生包。协议 `2.1.0-dev.1` 区分新语义，Python 分发为 `bugate-core 2.1.0a1`。安装器读取包内锁定兼容记录，支持精确旧 v2 包归档 rollback，不迁移任务绑定。本次交付本地产物，不覆盖公开 release。

真实性边界仍是受管观测、文件完整性与持久化发布，不能防御任意控制同用户文件的操作者。字段/引用静态检查不等于语义正确或执行真实。最终报告必须分开列明真实 DSH 确定性模型验收与 live-model 验证级别。
