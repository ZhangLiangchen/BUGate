# 验收范围与收敛改造合同

简体中文 | [English](CONTRACT.md)

2026-10-29 实现前冻结，基线为
`fe3e29b82059504cd47893b72005051489c0810f`。来源是当前会话中用户明确给出的
一至十三节实施请求和 SC-01～SC-18。主工作区起始干净，HEAD 与 origin/main
相同；保留已有其他工作树。DSH 报告版本 `0.2.2-alpha.2`，本轮另行核验实际类型和生命周期实现。

目标是在 v2 核心、统一 CLI 与 DSH 原生插件中实现第一等的版本化范围契约与收敛约束，
保留业务断言深度和真实证据。沿用现有 inventory 作为计划权威，不增加调度器或 Agent loop。
本次开发以用户请求及本合同/验收矩阵为启动依据，不要求尚未实现的机制先批准自身。

| 编号 | 不变量 | 可观测 Oracle |
|---|---|---|
| R1 | 用户目标固定广度，业务验证深度仍须充分。 | 仅有来源的目标分支进入必测；缺业务观测拒绝完成或验证。 |
| R2 | 明确要求的边界、拒绝、失败、权限和多个有限目标必须保留。 | 计划和运行保留指定分支，不自动扩展通用矩阵。 |
| R3 | 必需用例证明目标或必要前置条件。 | 契约、要求、流程、Oracle、预期证据和必要性关联完整；语义评审独立判断必要性。 |
| R4 | 建议不自动变成执行和阻塞。 | 记录建议不改变必测覆盖或完成授权；未经范围变更执行建议被拒。 |
| R5 | 辅助活动和有界诊断可用。 | 需求、数据、证据与清理通道可执行；诊断关联当前失败并强制预算。 |
| R6 | 变更有真实用户依据。 | 新版本和影响历史可追溯；模型自称授权不能获得完成许可。 |
| R7 | 评估、执行绑定准确契约、计划与快照。 | 旧令牌拒绝；复用证据核验要求、Oracle、对象和观测适用性。 |
| R8 | 真实失败和历史不被抹除。 | 失败执行可完成交付但业务验证失败；为隐藏失败缩减范围被拒。 |
| R9 | 恢复和任务隔离保持范围。 | 冷启动、压缩、子 Agent、preset 独立恢复；任务间不能交换授权或证据。 |
| R10 | 范围不能覆盖宿主权限。 | 受管工具仍受实际 guard、provider 和取消边界约束；不宣称能识别任意命令业务语义。 |
| R11 | 静态有效、语义判断、执行证据分别表达。 | 字段齐备和模型 pass 不足以证明业务正确。 |
| R12 | 产物可独立复验。 | 源码不可访问时安装/doctor/生命周期通过，已安装插件驱动真实 DSH 与临时 SUT。 |
