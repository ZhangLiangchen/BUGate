## 保留的工程边界

protocol/v2 是唯一机器规范，src/bugate 评估事实，DSH 负责执行、生命周期与有界返工；
views 投影规范，packaging 使用有限资源清单，方法文档负责解释。
保留来源命题、业务 Oracle、结构/语义/执行区分、真实失败/skip/xfail/未知、快照、权限、
路径/执行环境边界和证据持久化屏障。

锁定 Profile 继续固定需求/风险分母，scope revision 不得静默替代它。
同分母内用户明确调整范围，产生新 scope 版本并重新评估。
改变分母须显式创建新 Profile 版本并用既有初始化创建新任务，保留原任务及失败；
本次不新增同任务 Profile 迁移引擎。用户请求收据只证明范围来源，不替代 Profile 声明的领域证据。

本次使用订单、租户等示例不意味着任何 SUT 必须支持这些业务，也不产生通用安全/边界/性能必测矩阵。
测试验证的是 BUGate 如何服从 SUT 自己的有限要求；本开发矩阵不能投影成默认 SUT Profile 或 MethodSpec 要求。

## 完成标准与所有权

COMPLETE 的依据是真实目标、经来源核验的正式项 F-01～F-08、适用 v2 回归、安装包边界和真实 DSH 验收满足，
且代码、文档、产物和证据一致，无本轮未解决阻塞。**不再要求所有 SC 通过，也不追求固定测试数量。**
测试文件存在不等于已执行；真实宿主确定性 fixture 与 live model 分别报告；不授权公开 release/tag 发布。

INCOMPLETE/BLOCKED 应指出实际剩余要求或观察到的外部阻塞。不能把真实范围内缺陷改为可选，
不能削弱断言或删除失败证据。保留合理既有测试和历史结果，未采纳候选不得标成 PASS。

单写者不变：core_scope 负责协议/核心/核心测试；dsh_scope 负责 adapter/Skill/runtime；
packaging_delivery 负责打包/安装/CI/产品文档；主控负责来源纠正、集成、评审和最终提交。
