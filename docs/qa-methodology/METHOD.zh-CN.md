# BUGate v2 方法

[English](METHOD.md) | 简体中文

[Protocol v2](../../protocol/v2/manifest.yaml) 的 MethodSpec 与质量规则是机器权威，本指南解释其应用。

从证据建立可审计业务模型，区分事实、推断与未知，把用户故事转为命题、状态、边界和可观测 Oracle。来源引用证明可追溯性，不自动证明事实正确。通过可区分的观测处理冲突，保持未解决缺口可见。

先根据用户请求来源形成有限验收范围：目标、允许对象/环境、主流程和必要分支、要求、Oracle 与完成条件。区分明确指令、不可缺少的推导条件、未解决假设和范围外建议。“通常应该测”不能单独使场景成为必需项。

选择成本最低且充分的测试层，记录观测对象、前置条件、观测机制、判定期限、副作用与环境要求。缺少实现前提时，仍应允许读取需求及通过合法探索取得缺失证据。

锁定 Profile 固定任务内每个范围版本的需求/风险分母。同分母内用户授权的分支/Oracle 变化新建范围版本；改变分母须建立显式新 Profile 版本及新任务，保留旧任务和失败。请求收据证明用户选择，领域证据仍须由 Profile 声明。在当前验收范围契约内，把固定需求/风险追踪到命题、Oracle、用例、实现与执行。正例、负例、权限和边界是否必需，由用户目标和采纳要求决定；不自动套用完整测试类别矩阵。Profile 可要求原生领域、状态、维度、对抗工件，精确字段由 Artifact Schema 定义。有来源的语义评审与确定性结构检查分别记录。

使用宿主配置的采集器执行并保留真实结果，区分产品缺陷、测试基础设施/环境失败、零用例、skip、xfail、取消和未观测。断言来自契约与观测，不为适配缺陷放宽。诊断关联当前失败，记录假设、支持/反对证据与契约边界内的最小区分实验；达到边界后保存结论或阻塞，不生成新专项；知识记录来源、适用范围和确认状态。

声明绑定精确快照。业务理解不需要未来执行；需求验证需要当前 Oracle 关联的运行观测；完整交付按锁定 Profile 标准判断，可以包含真实产品失败。派生 QualityPosture 不是可编辑阶段或调度指令，DSH 负责执行与生命周期。

方法借鉴需求可追溯性、等价类、边界/状态测试、风险测试、独立评审及测试预言问题。未经过独立对照实验，不宣称提升缺陷发现率或模型效率。

范围外建议不能执行，也不阻塞完成。用户授权的范围变更新建不可变版本，保留失败，并重新评估计划与声明；新声明不能继承旧授权。报告列出实际约定范围，分别表达执行闭环、功能结果、阻塞与建议，见[范围示例](../ACCEPTANCE_SCOPE.zh-CN.md)。

官方 DSH Agent Team 按 Profile 声明的必要视角执行互审。宿主捕获作者、评审者、Team 成员、执行及输入上下文；fresh/fork 和执行分离是可观察事实，不保证认知独立。评审须具备持久化宿主观察、成功的最终工具结算、当前精确工件/输入绑定和有来源的语义内容。Team 任务完成和消息接受不等于评审有效。异议及处置保留可追溯关系；导入 JSON 和 reviewer 名称不能制造宿主来源。
